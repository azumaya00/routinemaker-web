# routinemaker API の Hono への作り直し 作業計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> この計画の実装は Codex（`codex exec --sandbox workspace-write`）に1タスクずつ任せる。Claude Code はコードを直接書かず、各タスクの後にテスト結果と差分を確かめる。

**Goal:** Laravel 版 routinemaker API と同じ動作の API を、routinemaker-web の中に Hono + Drizzle + Neon で作り、画面をそれにつなぎ替える。

**Architecture:** `src/server/` に Hono アプリを置き、`createApp(deps)` で DB・メール送信・Google 認証を外から渡す。本番では Next.js の `src/app/api/[[...route]]/route.ts` が本物の依存を渡し、テストでは PGlite（メモリ上の PostgreSQL）と偽のメール・Google を渡す。仕様の正は `laravel-final` タグ時点の routinemaker-api のコントローラー。

**Tech Stack:** Next.js 16.3.8 / Hono / Drizzle ORM（neon-http、テストは pglite） / zod / bcryptjs / arctic / nodemailer / Vitest

**Spec:** `docs/superpowers/specs/2026-10-23-hono-api-design.md`

## Global Constraints

- リポジトリ: `~/mockcode/app/routinemaker-new/routinemaker-web`、作業ブランチ `feat/hono-api`。各タスクの最後にコミットする。push はしない
- パッケージはタスク1で入れる一覧だけを使う（ユーザー確認済みのもの）。それ以外を足すときは止めて報告する
- `.npmrc` に `minimum-release-age=30240` を置き、公開から21日未満の版は入れない
- Codex はブラウザ（Chrome・Brave・Playwright など）を起動しない。E2E はタスク11で Claude Code 側が流す
- 応答の JSON の形・ステータス・メッセージは Laravel 版と一字一句同じ。英語のまま返っていた文言も英語のまま
- 日時はすべて UTC。JSON では ISO 8601 文字列（`Date#toISOString()`）
- ログイン状態の有効期限は120分。最後のアクセスから数え、残りが60分を切ったら延ばす
- メールアドレスの検索・一意性は `lower(email)` で行う。保存値は入力のまま
- コメントは自明でない箇所に「なぜ」だけを書く。Laravel のどのクラスに当たるかは、各ファイルの先頭に1行だけ書いてよい
- 旧 DB のダンプ（個人情報入り）はリポジトリに入れない。テストには架空のデータだけを使う

## Review Focus

1. 大文字を含むメールアドレス（`Foo@Example.com`）でのログイン・登録の重複判定・再設定・Google 照合 → 小文字と同じ人として扱う（タスク3・4・5にテストあり）
2. 期限切れ、または退会済みユーザーのセッション Cookie → 401 `{"message":"Unauthenticated."}`（タスク2にテストあり）
3. 他人のルーティン・履歴の id、数字でない id → 404（タスク7・8にテストあり）
4. Laravel 時代の `$2y$` 形式のパスワードハッシュ → ログインできる（タスク2にテストあり）
5. Origin ヘッダーがない、または別ドメインからの POST → 403 で拒否し、DB を変えない（タスク2にテストあり）

## 共通のインターフェース（タスク1で作り、以降の全タスクが使う）

```ts
// src/server/types.ts
export type Mailer = {
  send(msg: { to: string; subject: string; text: string; html: string }): Promise<void>;
};
export type GoogleProfile = { sub: string; email: string | null; name: string | null };
export type GoogleOAuth = {
  createAuthorizationURL(state: string, codeVerifier: string): URL;
  validateCallback(code: string, codeVerifier: string): Promise<GoogleProfile>;
};
export type AppDeps = {
  db: Db;            // src/server/db/client.ts
  mailer: Mailer;
  google: GoogleOAuth;
  appUrl: string;    // 例 "https://routinemaker.yuru-labo.com"（末尾の / なし）
  now?: () => Date;  // テストで時刻を固定する。省略時は new Date()
};
export type AppEnv = { Variables: { user: UserRow; sessionToken: string } };
```

- `Db` は neon-http と pglite のどちらの Drizzle インスタンスも受けられる型にする（`PgDatabase<PgQueryResultHKT, typeof schema>` など）。トランザクションは使わない（neon-http では使えない）
- `UserRow` などの行の型は `schema.ts` から `typeof users.$inferSelect` で作って export する

**Interfaces:**
- Produces:
  - `hashPassword(plain: string): Promise<string>`（bcryptjs、cost 12）
  - `verifyPassword(plain: string, hash: string | null): Promise<boolean>`（hash が null なら false。`$2y$` は `$2b$` に置き換えてから照合する）

  - `setSessionCookie(c, token: string)`（httpOnly、Secure、SameSite=Lax、Path=/、Max-Age=7200）、`clearSessionCookie(c)`
  - `requireAuth`（`c.var.user`・`c.var.sessionToken` を入れる）、`requireAdmin`、`csrf`（appUrl を使う）、`rateLimit(bucket: string, max: number)`（1分あたり）

- [ ] **Step 2: 落ちることを確かめる** — Run: `pnpm test` / Expected: FAIL

- [ ] **Step 3: 実装する**

`rateLimit` は rate_limits に1行足す前に、`key` が同じで `created_at > now-60秒` の行数を数え、max 以上なら 429。記録のついでに `created_at < now-60秒` の行を消す。key は `${bucket}:${ip}`。IP は `x-forwarded-for` の先頭、なければ `x-real-ip`、それもなければ `"unknown"`。csrf は GET・HEAD・OPTIONS 以外で `Origin` が `new URL(appUrl).origin` と一致しなければ 403。
